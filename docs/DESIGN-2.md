# Opaline 2.0 design language (outline)

Status: **outline** (2026-11-25). Filled in during P1 after you pick one of the three visual directions (PLAN-2 task
1.1); theme chapters are completed in P4. Values marked *proposed* are starting points, not decisions.
`docs/DESIGN.md` stays the reference for the 1.1 system, which ships as the **Classic** theme.

## 1. Principles
- One hero per widget and size; the composition is designed per widget and per size, not one template.
- The wallpaper is part of the design: see-through by default, readable by adapting text before adding tint.
- Progressive disclosure: essentials first, everything else one level deeper.
- Shapes and color carry meaning (heat, sleep, charge, weather), never decoration alone; status is never color alone.
- Labels are never cut; user data may end in an ellipsis at a word boundary.
- Idle means no frames; reduced motion is respected everywhere.
- Original work only: no Apple or Google assets, fonts, icons, logos or trademarked names.

## 2. Theme model
How a theme is built (maps to `theme.json`, §5.2 of the brief):
- **Tokens**: color source and scheme (or a fixed palette), type scale, shape language, motion personality, glass
  defaults, spacing and density.
- **Style layers**: global, per widget kind, per role or block id.
- **Layouts**: optional compositions per widget kind and size.
- **Assets**: fonts (with licenses), images, `theme.css`.
- **Starter layouts**: shown in onboarding and Settings → Looks.

## 3. Type
- 3.1 Roles: `hero`, `title`, `label`, `value`, `caption`, `accent` (+ `unit`, sharing the hero's baseline).
- 3.2 Opaline scale (*proposed*, refined in P1):

  | Role | Size (S / M / L) | Weight | Width (`wdth`) | Notes |
  | - | - | - | - | - |
  | hero | auto-fit, ~40 % of the card height at S and M | 650–800 | 25–100, narrower for long numbers | tabular figures, Roboto Flex |
  | unit | 0.45 × hero | 500 | as hero | same baseline |
  | title | 15 / 16 / 17 | 600 | 100 | short; often hidden |
  | value | 14 / 15 / 16 | 500 | 100 | tabular |
  | label | 12 / 13 / 13 | 500 | 100 | explicit short form per field |
  | caption | 11 / 12 / 12 | 400 | 100 | lower emphasis (on-surface-variant) |
- 3.3 Auto-fit rules: font size and width axis within bounds; never below the role's minimum.
- 3.4 Fonts per theme and lazy loading; Arabic fallbacks; `text-scaling-factor`.
- 3.5 OpenType features used (tabular figures, slashed zero, stylistic sets).

## 4. Widget anatomy
- 4.1 Hero, secondary, captions; header styles (glyph + title, title, glyph, none) and when each is used.
- 4.2 Padding, gap and concentric radii per size class (carried over from `DESIGN.md` §1–2, adjusted per theme).
- 4.3 Per-size intent: 1×1 and 2×1 complications; 1×2 vertical controls; S and M glanceable; 2×4 Tall and 6×4 Wide;
  L and XL small dashboards.
- 4.4 Interaction affordances (buttons, toggles, sliders inside widgets) and their hit sizes.

## 5. Responsive rules
- 5.1 Element priorities and the degradation order: hide icon → explicit short label → hide label (tooltip and
  accessible name keep it) → drop lowest priority → denser variant.
- 5.2 Short labels are written per field and per language; never generated by cutting.
- 5.3 User data truncation (word boundary, ellipsis) and where it's allowed.
- 5.4 Breakpoints for free sizes; container queries or measured breakpoints (ADR from spike S2).
- 5.5 The Lab checks that enforce this (zero truncation, contrast).

## 6. Color
- 6.1 Scheme pipeline (unchanged: material-color-utilities, wallpaper / accent / custom source).
- 6.2 **Color identity per widget kind** (*proposed*), harmonized with the scheme in HCT and overridable:

  | Kind | Accent family |
  | - | - |
  | CPU | thermal (teal → amber → red by temperature) |
  | Memory | violet |
  | GPU | magenta / green by vendor-neutral hue |
  | Storage | amber |
  | Network | cyan |
  | Battery & Power | green (amber/red when low) |
  | Fans | thermal, muted |
  | Weather | condition-driven (sky) |
  | Calendar | the calendar's own color |
  | Now Playing / Visualizer | from the album art |
  | Clock, World clock | neutral, scheme primary |
  | Developer & Online | per service, neutral by default |
- 6.3 Semantic ramps (thermal, load, health) and the "never color alone" rule.
- 6.4 Desktop look modes: Glass · Clear · Tinted · Dark · Light · Dimmed, and the master transparency slider.

## 7. Shape
- 7.1 Card shapes: continuous squircle corners (corner smoothing), per-corner radii, library shapes.
- 7.2 Meanings: CPU heat badge circle → cookie → burst; sleeping GPU → moon/pill; battery liquid pill with bubbles;
  weather condition shapes; Wi-Fi signal shape; shape masks for art and photos, breathing with the bass.
- 7.3 Morph rules: when shapes morph, duration and springs, reduced-motion substitutes.

## 8. Glass 2.0 and see-through
- 8.1 The layer stack per surface: backdrop sample (blur level from the pyramid), refraction band, dispersion, tint
  (color or gradient), inner glow, specular highlight, rim, depth shadow, grain, border.
- 8.2 Parameter ranges and defaults per theme (blur 0–100 where 0 is sharp; tint 0–100 independent of blur).
- 8.3 True alpha vs. full-resolution sampling: the default and the option (ADR 0012).
- 8.4 Legibility 2.0: text color from the local backdrop, halo/shadow, vibrancy text, tint raise last and only with
  "Keep text readable"; the contrast meter and the 4.5 : 1 warning.
- 8.5 Opaque mode (reduce transparency, high contrast) wins over everything.
- 8.6 What CSS can and can't style (the glass is WebGL).

## 9. Motion
- 9.1 Spring tokens (unchanged from `DESIGN.md` §6) and per-theme motion personalities (e.g. Bloom bouncier,
  Crystal calmer, Terminal instant).
- 9.2 Staggered entrances; value changes as odometer or crossfade; hover lift or 3-D tilt with a following
  specular highlight; press 0.97; shared-element morphs between sizes; theme-switch transitions.
- 9.3 Ambient motion (skies, auras, fan spin) only while visible and not covered; reduced motion and dimmed rules.

## 10. Icons
- Material Symbols Rounded, Outlined, Sharp (Apache-2.0), subset per set; fill, weight, grade; app icons from the
  system icon theme for processes, launchers and peripherals.

## 11. The nine looks
One chapter each, with: character, type, shape language, surface treatment, motion personality, hero visuals, clock
faces, color handling, starter layouts, Lab sheet.
- 11.1 **Opaline** (default): the direction chosen in P1.
- 11.2 **Crystal**: clear glass, squircles, large heavy numerals, almost no labels.
- 11.3 **Bloom**: library-shape cards, tonal containers, wavy progress, playful morphs.
- 11.4 **Air**: frameless, haloed text, widgets floating on the wallpaper.
- 11.5 **Terminal**: JetBrains Mono, box-drawing frames, TUI bars and sparklines, ANSI-like palette from the wallpaper.
- 11.6 **Neon**: dark surfaces, glowing gradient outlines, synthwave palette, Space Grotesk.
- 11.7 **Paper**: matte and light, Fraunces with a grotesk, hairlines, no glass.
- 11.8 **Mono**: monochrome, high contrast, e-ink calm; the Dimmed state's natural partner.
- 11.9 **Classic**: exactly 1.1 (`DESIGN.md`).

## 12. Signature layouts per widget
A page per widget (filled in P4): sizes supported, the hero at each size, element priorities, detail view, states
(loading, unavailable, asleep, needs permission, empty/auto-hide, alert), and Lab references.

## 13. States
Resting, hovered, pressed, lifted, dimmed, alert, loading, unavailable/asleep/needs permission, auto-hidden; how
each theme expresses them.

## 14. Accessibility and i18n
Contrast targets, focus rings, keyboard order inside compositions, generated accessible names, reduced motion, text
scale; RTL inside widgets while grid positions never mirror; Arabic type pairing per theme.

## 15. The Lab
Theme switcher, light and dark wallpapers, widget × size × theme × state matrix, the zero-truncation and contrast
checks, and which combinations have stored baselines (PLAN-2 decision 5).
